# Симулятор етичних дилем (Ethical Dilemmas Simulator)
### Веб-додаток (PWA) для IV Хакатона з питань виховання доброчесності та запобігання корупції (Завдання 1)

> **Освітній симулятор прийняття рішень у секторі безпеки та оборони України** на основі ситуацій з Посібника CIDS № 1/2025 («Посібник з вирішення дилем на робочому місці у державному секторі»).

---

## 1. Головні принципи та етичні гарантії («Що система НЕ робить»)

Проєкт побудовано за найвищими стандартами інституційної етики та безпеки:

1. **100% детермінований runtime (Без LLM у продакшені):**
   - Симулятор **НЕ звертається до жодних генеративних нейромереж під час проходження**. Усі розгалуження, варіанти, наслідки та норми визначені у відкритих перевірених JSON-файлах окремо від коду.
2. **Zero PII & Anti-Profiling (Захист від стеження та оцінювання осіб):**
   - **Жодної реєстрації, логінів, паролів, ПІБ, військових звань чи email.**
   - Прогрес одиночного проходження зберігається **виключно локально** в `localStorage` браузера користувача і ніколи не передається на сервер.
   - У груповому режимі кімнати існують лише в оперативній пам'яті (ephemeral RAM), не зберігають IP-адрес чи пристроїв і автоматично знищуються після завершення заняття. Фіксуються лише анонімні лічильники голосів (`{ "A": 14, "B": 8 }`).
3. **Заборона сумування балів (Ціннісний компроміс замість ярликів):**
   - Три осі (`dobrochesnist`, `efektyvnist`, `dovira`, від `-2` до `+2`) відображають моральний та управлінський trade-off, а **НЕ оцінку людини**.
   - У системі **відсутній єдиний сумарний бал**. Система принципово не навішує ярликів («корупціонер», «нечесний» тощо) — оцінюються лише вчинки та їхні правові наслідки.
4. **Не для атестації чи оцінювання персоналу:**
   - Симулятор є суто навчальним тренажером для розвитку критичного мислення та аналізу ризиків.

## 2. Структура сценаріїв

Всі сценарії зберігаються у відкритому людино- та машиночитаному форматі в папці `/stsenarii/*.json` відповідно до JSON-схеми `/schema.json`:

### А. Сценарії команди (Повноцінні 3+ етапи рішень)
1. **`S06-reviziia-na-skladi.json`** (за мотивами Ситуації №18 CIDS):
   - *Роль:* Уповноважена особа з питань запобігання корупції / офіцер штабу.
   - *Конфлікт:* Систематична недостача продуктів на польовому складі; начальник логістики — рідний брат командира частини (порушення ст. 27 Закону), командир тисне й погрожує доганою та переведенням.
   - *Норми:* `ZPK-1`, `ZPK-27`, `ZPK-28`, `ZPK-29`, `ZPK-42`, `ZPK-44`, `ZPK-53-1`, `ZPK-53-4`, `ZPK-53-5`, `ZPK-3-1-g`, `NAZK-R4-194`, `SVS-36`.
2. **`S07-terminova-lohistyka.json`** (за мотивами Ситуацій №13, №16 та №19 CIDS):
   - *Роль:* Командир підрозділу забезпечення.
   - *Конфлікт:* Термінова передислокація боєприпасів та поломка вантажівок; підлеглий пропонує ремонт за пальне на приватному СТО без чеків, а фермер пропонує ангар «під чесне слово».
   - *Норми:* `ZPK-22`, `ZPK-42`, `ZPK-3-1-g`, `NAZK-R4-194`, `SVS-30`, `SVS-36`.
3. **`S08-kadrovyi-vidbir-pid-tyskom.json`** (за мотивами Ситуації №37 CIDS — ідеальний для 3-5 хв демо):
   - *Роль:* Офіцер, член конкурсної комісії відомства.
   - *Конфлікт:* Старший начальник (генерал), який погоджує ваше призначення комбригом, просить «посприяти» його протеже, яка слабша за кандидата-ветерана.
   - *Норми:* `ZPK-1`, `ZPK-28`, `ZPK-29`, `ZPK-41`, `ZPK-44`, `ZPK-3-1-g`, `NAZK-R4-194`.

### Б. Стартові приклади від організаторів (2 етапи)
- `S01` — Подяка від батьківського комітету (подарунки).
- `S02` — Кандидат — син побратима (конфлікт інтересів).
- `S03` — Акт на пальне (викривач та тиск).
- `S04` — Курсова за ніч (академічна доброчесність та ШІ).
- `S05` — Машина для доброї справи (службове майно).

## 3. Функціональні можливості

- **Одиночний режим (Режим навчання):**
  - Екран брифінгу з ролями та прихованим конфліктом цінностей.
  - **Інтерактивний помічник CIDS 2025:** 4 типи дилем Рашворта Кіддера та «Тест із 5 перевірок» (розділ 4.2 CIDS) перед вибором.
  - Екран зворотного зв'язку: наслідки «Одразу» та «Згодом», 3 роздільні шкали дельт балів, клікабельні чипси норм із показом цитат, редакцій та посилання на `zakon.rada.gov.ua`.
  - Підсумкова карта пройденого шляху, застосовність норм та поради.
- **Груповий режим для занять (Classroom Mode):**
  - Викладач генерує кімнату з 6-значним кодом та **живим QR-кодом**.
  - **Режим проєктора** для читання з великих екранів у лекційних аудиторіях.
  - Анонімне онлайн-голосування зі смартфонів слухачів/курсантів без встановлення додатків.
  - Автоматичний розрахунок **«Індексу дискусії»** (поляризації аудиторії від 0.0 до 1.0) та показ запитань для обговорення.
- **Конструктор сценаріїв (No-Code Editor):**
  - Повноцінний візуальний редактор із вибором норм із `normy.json`.
  - **Живий інтерактивний SVG-граф рішень** із підсвіткою недосяжних чи висячих вузлів.
  - Миттєва перевірка за правилами `schema.json` та `zibraty.py`.
  - Кнопки тестування в симуляторі, імпорту/експорту JSON.
- **Експорт у SCORM 1.2 (Moodle / «Дія.Освіта»):**
  - Генерація валідного ZIP-пакета (`imsmanifest.xml`, автономний оффлайн плеєр `index.html`, `scorm-api.js`).
  - Передає до LMS **виключно факт проходження** (`cmi.core.lesson_status = "completed"`), принципово не передаючи відповіді або бали за доброчесність.
- **100% Оффлайн PWA:**
  - Service Worker кешує всі ресурси; працює в бомбосховищах або закритих класах без доступу до Інтернету.
- **Двомовний інтерфейс (UKR / ENG):**
  - Миттєвий перемикач мови елементів UI, з повним збереженням автентичних українських юридичних норм та сюжетів.

## 4. Швидкий старт та запуск

### Вимоги:
- Node.js 18+ або 20+
- Python 3.10+ (для валідатора `zibraty.py`)

### Варіант А. Запуск у режимі єдиного сервера (Production / Клас):
```bash
# 1. Встановити залежності
npm install

# 2. Зібрати фронтенд
npm run build

# 3. Запустити єдиний сервер (роздає клієнт + WebSocket кімнати)
npm start
```
Сервіс доступний за адресою:
- Локально: `http://localhost:3000`
- У локальній мережі класу по Wi-Fi: `http://<IP_комп'ютера_викладача>:3000`

### Варіант Б. Режим швидкої розробки (Dev Mode):
```bash
# Запуск Vite сервера з гарячим перезавантаженням
npm run dev
```

### Варіант В. Запуск у Docker:
```bash
docker compose up --build
```
Додаток буде доступний на порту `3000`.

## 5. Валідація та тестування

### Перевірка JSON-схеми та збірка Markdown:
```bash
python3 zibraty.py
```
*Результат:* перевіряє всі 8 сценаріїв на цілісність графів, унікальність ID, regex `^[A-Z][0-9]?$`, норми та оновлює `stsenarii.md` і `perelik-norm.md`.

### Автоматичні тести продукту:
```bash
npm test
```
*Перевіряє:*
1. Синтаксис і валідність усіх 8 сценаріїв.
2. Гарантію глибини >= 3 послідовних етапів у сценаріях команди S06, S07, S08.
3. Унікальність і відповідність regex ID варіантів.
4. Звірений статус усіх використаних норм у `normy.json`.
5. Повну відсутність персональних даних у кімнатах групового режиму (Zero PII).
6. Математичну точність індексу дискусії (розколу думок).
7. Відповідність експорту SCORM 1.2 політиці конфіденційності.
8. Незалежність трьох вимірів компромісу без загальної суми.
